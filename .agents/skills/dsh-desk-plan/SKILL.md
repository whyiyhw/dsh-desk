# dsh-desk 计划执行手册

**唯一规范源是 `docs/spec-and-plan.md`(v1.1,基线 `5e0c2af`)**。本 skill 是它的执行索引与硬约束摘要:先读这里,涉及具体实现时再读文档对应小节。若两者出现冲突,以文档为准,并顺手修掉本 skill 的过期内容。

## 硬约束(任何改动不得违反)

1. **稳定表面契约**:dsh-desk 只依赖 dsh stdout 打印的 `dsh web:` 就绪行,不逆向、不依赖 DSH 内部实现。解析按字面量 `dsh web:` 切分、取其后首个以 http 开头的空白分隔 token(S1 落地后的语义),不要引入更深的解析去"抗漂移"。
2. **token 脱敏先于一切发布物**:带认证 token 的就绪行不得明文进日志文件、诊断文案或"贴日志"引导(S1)。任何 release artifact 产出前,先确认脱敏已落地——日志一旦落到用户机器上就无法召回。
3. **生命周期代数语义**(S2):stdout 监视线程与超时定时器只在自身代数 == 当前代数时才允许改变状态;旧代线程读到 EOF 必须安静退出。重试与 Restart 走同一条"杀净 → 等退 → 再起"串行路径,禁止"未杀先起"。不得跨 `spawn()` 持有 child 字段锁(托盘主线程会同步调 kill_server,长持锁卡 UI)。
4. **Windows 优先**:路径与进程树杀(`taskkill /T /F`)按 Windows 语义;macOS/Linux 是 S11,defer,不提前铺路。
5. **回归契约 §2.4**:每次交付前走查文档 §2.4 的六条可观察契约(认证跳转 / 托盘四项 / 热键 / 二次启动 / 关窗藏托盘 / Quit 后无 dsh/node 残留)。这是"零回归"的可判定定义,不要用含糊的"应该没坏"替代。

## 阶段与门禁(顺序不可跳)

| Phase | 内容 | 门禁(不通过不得进下一阶段) |
|---|---|---|
| 0 | 处置 `ws-probe.cjs`、提交 `docs/`、真机冒烟、push CI(`cargo check`) | git 干净 + §2.4 基线记录在案 |
| 1 | S1(被动提示/超时降级/前缀放宽/日志脱敏)+ S2(代数标记);上游 issue 确认就绪行稳定性 | S1/S2 验收逐条通过 + §2.4 契约走查 |
| 2 | S3 CI+安装包、S4 首跑引导、S6 图标、S12 发布物料、S5a 轻量更新检查 | 干净 Windows 虚机仅按 README 装包到达 Ready |
| 3 | S5b 原地更新(门禁 Q2,可选)+ P2 择优(S9/S13 最可能) | S5b 验收(若启用)+ §2.4 契约 |

做某项工作前,先读 `docs/spec-and-plan.md` §2.3 对应 S 项的**验收标准**——那是完成定义,不是参考意见。

## 工作协议

- **行号是快照**:文档中的 `lib.rs:NNN` 锚点基于 `5e0c2af`,Phase 1 改动落地后即过期。引用前先对当前代码核实,不要拿旧行号当事实。
- **决策已定的不重开**:文档 §5 决策记录里的结论(受众 = dsh 社区、S5a 默认 / S5b 可选、跨平台 defer、不逆向 DSH 内部等)直接沿用,不要重新论证。Q1(代码签名)/ Q2(更新私钥)/ Q4(winget)是留给用户的决策:不替用户拍板,按默认路径继续,并在交付说明里标注该决策点仍开放。
- **改计划本身**:范围或验收变更时,直接更新 `docs/spec-and-plan.md`(唯一规范源),在其 §5 决策记录加一行,并同步本 skill 的索引表;不要在别处另立第二份计划文档。
- **实现 S 项的交付物**:代码改动 + 该项验收标准的自验记录(怎么测的、结果如何)+ §2.4 走查结果,三者齐才算完成。
- **回合末独立审查**(S 项代码交付的第四道门):交付前开一个**无作者上下文的新会话/子代理**,喂本次 diff + 本 skill 硬约束 + 仓库 AGENTS.md 红线,只带三项核对指令(违反约定没?文档过时没?生命周期/并发风险没——锁跨 spawn、旧 watcher 反噬、代数一致性),让它输出带位置的问题清单;改不改作者拍板。同一 AI 自查无效——它带着答案查自己。
- **收尾反思(做完 ≠ 交付,报告"完成"前必过)**:①自验记录与 §2.4 走查结果落盘到 `docs/verification-<日期>-<S项>.md`,对话里的口头报告不算;②本轮新坑回写仓库 `AGENTS.md` 台账,**被推翻的旧结论当场修正**;③spec §5 加交付事实行(有/无范围变更都加);④环境还原清点(config 还原、无孤儿 dsh/node、%TEMP% 注入物注明);⑤写一句可执行的反思教训。清单全文见仓库 `AGENTS.md`"收尾反思机制"节。
- **docs 命名即分类**:`verification-<日期>-<S项>.md` / `postmortem-<日期>-<主题>.md`,索引与拆子目录触发条件见 `docs/README.md`;未达触发条件前不建子目录。
